The feed now spots like CW Skimmer Server — each station once where it calls, at its frequency — and a fix for a Red Pitaya shared with another skimmer. New: a waterfall tab, a callsign filter, a spot archive, the CPU temperature.

## Feed: one spot where the station calls

Measured against CW Skimmer Server on the same antenna and against RBN, by replaying this skimmer's live decodes from 17–18 November through the new code (design and numbers: [`docs/LIVE-AIR.md`](https://github.com/ok1hra/skimmer-for-linux/blob/v0.8.2/docs/LIVE-AIR.md#spot-frequency-snap-not-crawl-2026-11-18)):

| | CW Skimmer Server | v0.8.1 | v0.8.2 |
|---|---|---|---|
| weekday afternoon: spots per station | 1.77 | 2.33 | 1.67 |
| weekday afternoon: again within a minute | 3.8 % | 6.3 % | 0.5 % |
| CWT evening: spots per station | 2.09 | 3.52 | 2.01 |
| CWT evening: again within a minute | 5.8 % | 26.0 % | 4.1 % |
| CWT evening: over 150 Hz off RBN's frequency | 4.3 % | 20.9 % | 9.1 % |
| 17.5 h, 7 bands: over 150 Hz off RBN's frequency | — | 12.7 % | 5.0 % |
| median time between spots of a station | 10 min | 2.5–5 min | 10 min |

29–43 % fewer spots, the same stations on their right frequency (1–4 fewer per window, at its edges: spotted minutes before it). Three changes in the station table and the feed:

- **Snap, not crawl.** A stronger read of a station calling more than 100 Hz from where the table had it moves it there at once. Before, it moved 30 % of the way per read and the feed re-spotted every step of 100 Hz or more — LZ1ZF went out on 7016.7, 7017.1, 7017.4, 7017.6, 7017.7 and 7017.9 within a second for a carrier on 7018.0. A call heard in somebody else's exchange ("RV6HV 5NN" on the runner's frequency) no longer drags the station at all. `SKIM_ST_SNAP=0` brings the old behaviour back.
- **One place at a time.** A station read again on its own frequency in the last 30 s stays there when its call turns up kHz away — in a contest it is answering someone else there. In the CWT, PA3AAV flipped between its CQ on 3540.9 and SP3FSM's 3536.0 every second. A real QSY moves it after the hold. `SKIM_ST_HOLD=0` turns it off.
- **A pause is not a new spot.** The feed remembers what it sent for its full 10 minutes, no longer only while the station is in the 2-minute table: a station that paused for two minutes is not spotted again on the same frequency. `SKIM_RBN_MEMO=0` turns it off.

## Red Pitaya shared with CW Skimmer Server

The Red Pitaya server takes control commands from anyone, and its receiver count and frequencies are whatever the last command said. When another program took the radio over, this skimmer kept refreshing its settings for up to 2 s, until it noticed — and CW Skimmer Server, which sends its settings once, then read our 7-receiver data as its 8-receiver layout: every call on several bands at once at wrong frequencies, WPM 10 % too high, all of it sent to RBN (live 17–18 November). Now:

- settings are repeated only in the first 3 s after the start, and only while the stream is coming to us;
- if the stream still comes to us but in a layout we did not ask for, the log says another client reconfigured the receiver and our settings go out again;
- the stop at exit goes out only if the stream was still ours a moment ago — it no longer ends another program's stream.

## Web page

- **Waterfall** tab: one band, live, the height of the page — span down to 1.5 kHz, speed, contrast, the spectrum above it, the spotted calls standing in it. Computed only while someone watches; a few kB/s per viewer.
- **Callsign filter** (Settings): IP-rotator's DX filter — part of a call or a regular expression (ticking Regex on an empty field offers IP-rotator's "everything but Russian and Belarusian calls"); a call that does not match makes no station, spot, feed line, map dot or count. Optionally drop your own call and its busts a character or two off it (calls MASTER.SCP knows still pass). Empty = off, as before.
- **Spot archive** (Settings): every spot sent, one gzip file per UTC day (`YYYYMMDD-spots.gz`, a tab-separated line per spot). Empty = off.
- **Statistics**: the CPU temperature under the CPU chart and on the status bar; one crosshair through all charts; the whole history in small above the time slider; CW blue and RTTY teal everywhere.
- Status: the map, the cluster and the band ladder show the last 30 minutes, every readout says over what period, frequencies with a space after the MHz.

## Before you upgrade

- **The statistics file goes to version 4** (the CPU temperature) at the first start. The version 3 file is kept beside it as `stats.bin.v3` — v0.8.1 would start a fresh history on a version 4 file, so put that one back before going back to v0.8.1.
- The feed sends a third fewer spots than v0.8.1 (29–43 % in the windows above), the same stations.
