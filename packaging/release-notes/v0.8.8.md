The skimmer now keeps itself up to date: once a day it looks at its latest release on GitHub and swaps a newer version in by itself, at an hour you choose. The decoder, the feed and the web page's other parts are as in v0.8.7.

## Updates (Settings → Updates)

- **Once a day** the skimmer asks GitHub for its latest release. Drafts and prereleases are never taken. The time of the last look is kept, so restarts send no extra request.
- **`mode=auto` (the default):** a newer version is downloaded beside the running AppImage at once and checked:
  - its sha256 must match the digest GitHub publishes for the file; a release without one is refused;
  - it is run once on this machine's config: `--version` must name the release and `--check-config` must pass.
  
  At `hour_utc` (default 03 UTC) the new file is renamed over the running one and the skimmer restarts into it. The old file stays as `<file>.prev`.
- **`mode=notify`** only shows that a newer release is out; **`mode=off`** never asks GitHub.
- **The Settings box** shows the running version, the latest release with a link to it, the last look and its result, a downloaded version waiting for its hour, and the one kept. Its buttons are *Check now*, *Install now* and *Back to* the version before. Managers see a newer or downloaded version in the page's header too.
- **Back by itself:** a version that crashes three times within 15 minutes of an update is swapped back out, and that version is not tried again; the next release is. This needs something that starts the skimmer again after a crash: the systemd service (see below) or a supervisor.
- Only a release AppImage in a directory it may write updates itself. A development build or a program from a build tree only reports a newer release.

## Also new

- `--version` prints the version (and, for a development build, its commit).

## Before you upgrade

**Name the file without its version,** e.g. `skimmer-headless-x86_64.AppImage`, and start that name (start script, `--install-service` again after renaming). An update keeps the file's name, so a versioned name would no longer say what is inside.

This release has to be installed by hand once; the ones after it come by themselves. To keep doing it by hand, set `[update] mode=notify` or `off` before the first start. v0.8.7 ignores the new `[update]` section.

## Run it as a service

Started in a terminal, the skimmer runs until Ctrl+C. Nothing starts it again after a reboot or a crash. Running it as a systemd user service is the other way, and the one that suits updates:

- it starts at boot, even before anyone logs in;
- it starts again a minute after a crash or a lost stream, and a crashing update goes back to the version before it;
- its log is in the journal.

Stop a skimmer running in a terminal first, because two of them would fight over the radio and the web port. Then:

```sh
./skimmer-headless-x86_64.AppImage --install-service
systemctl --user enable --now skimmer-headless
loginctl enable-linger $USER                       # once: start at boot, keep running while logged out
journalctl --user -u skimmer-headless -f           # the log
```

The README's *As a service* section has the rest: restart, stop, and your own settings in a drop-in.

## Install

```sh
mv skimmer-headless-0.8.8-x86_64.AppImage skimmer-headless-x86_64.AppImage
chmod +x skimmer-headless-x86_64.AppImage
./skimmer-headless-x86_64.AppImage
```
