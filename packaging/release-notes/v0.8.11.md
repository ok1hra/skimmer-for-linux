A new CW engine to choose per band, **CW v4** (DeepCW v2 narrow, a neural decoder run on the CPU with no extra download), a redesigned bands table with one mode filter for the whole page, and three fixes for things that left a skimmer down: the FT8/WSPR crash of 0.8.10, a radio left busy by our own dead stream, and a SIGBUS at every service stop. The default CW engine stays v3.1; its decodes and feed lines are as in v0.8.10.

## CW v4 — DeepCW v2 narrow

- **What it is:** e04's DeepCW v2 *narrow* model (MIT) run by our own forward pass in C (AVX2, SSE or plain C, picked at start). There is no ONNX Runtime and no GPU, and the weights are built into the AppImage.
- **Why:** on the same channels as v3 (SDRIAK's measurements) it is 2.5–5 dB more sensitive in white noise and 7–14 dB more under slow fading, and it wrote no false text in 20 h of noise. It is weaker than v3 above 45 WPM, under fast flutter and drift, and at ≤ 12 WPM.
- **Calls are still checked:** a word that looks like a call is scored against the MASTER.SCP calls near it with the network's own probabilities. Only dictionary calls confirmed this way go out as corrections, the same rule as v3. A call torn before its digit is joined.
- **Choose it per band** (`cw:v4` in `[bands]`, or Settings → Bands) or for all bands (`[decode] engine=v4`). The header lists every CW engine in use with its bands, e.g. `cw-v3.1 · cw-v4 40m 20m`.
- **The compute check:** Settings measures what this CPU can do and compares it with the week's peak of active CW decoders. When that is short, it says so and asks before saving v4.
- **The load guard** (`[decode] v4_guard`, on by default): if the decoders fall behind for 3 of 5 minutes, the quietest v4 band is paused. One band always stays, and a paused band comes back after 20 calm minutes. `[decode] v4_workers` sets the decoder threads (0 = half the CPUs).
- The old DeepCW engine is now called **DeepCW v1** (key `deepcw` unchanged).

v4 needs a live verdict before it can become the default. It has run on 40 m and 20 m of OK1HRA's skimmer since 2026-11-23.

## On the web page

- **The bands table has two columns:** *spots* and *active decoders*. Each bar is split by mode, in the order and colours of the legend above it: CW, RTTY, FT8, FT4, WSPR. The legend shows only the modes that run.
- **One mode filter for the whole page:**
  - the eye at each mode in the legend turns that mode off: its part of the bars stays, grey, and its spots leave the counts, the continents' heat map, the map and the DX cluster;
  - the DX cluster's *Mode* menu is the same filter, so either one sets the other.
- **The age filter is in view:** *5 · 10 · 15 · 30 min* in the map's title, the same filter as the DX cluster's UTC column. The bands table, the heat map and *spots in N min* follow it too.
- **A status column** says what a band is doing instead of a bare `TEST`:
  - the thermal guard's trial of a paused band, `thermal test till 15:11 · 1 spot`, with a tip saying what keeps it on;
  - a band paused by the thermal guard or the v4 load guard;
  - a worker.
- Active FT8/FT4 stations (heard in the last minute) and the latest WSPR cycle's stations count as active decoders.

## Fixes

- **FT8 and WSPR no longer crash the skimmer.** 0.8.10 aborted after a few hours with FT8 on (`g_mutex_clear() called on uninitialised or locked mutex`). GLib breaks when two threads wait on helper programs with a cancellable, so the helpers now run without one.
- **The helpers die with the skimmer.** If the skimmer is killed, the FT8 and WSPR decoders end too instead of running on.
- **A radio left busy by our own dead run is freed.** The Red Pitaya has no watchdog: a skimmer that died without stopping its stream left the radio busy, and every restart gave up with "no free radio". The skimmer now notes each stream it starts. If the radio is busy with a stream it noted, and nothing on this machine still listens on that port, it stops that stream itself. A stream that belongs to another client is never stopped.
- **No SIGBUS at a service stop.** systemd sent SIGTERM to the AppImage's FUSE helper as well, so the image was unmounted under the exiting skimmer (`status=7/BUS` in the journal). The unit now has `KillMode=process`.

## Install

A skimmer on v0.8.8 or later with `[update] mode=auto` (the default) installs this release by itself at its update hour; Settings → Updates → *Install now* does it at once. By hand:

```sh
mv skimmer-headless-0.8.11-x86_64.AppImage skimmer-headless-x86_64.AppImage
chmod +x skimmer-headless-x86_64.AppImage
./skimmer-headless-x86_64.AppImage
```

**If it runs as a systemd service, run `--install-service` once more** (`./skimmer-headless-x86_64.AppImage --install-service`) to get `KillMode=process`. A skimmer started from an older unit says so in its log.
